# Security and privacy

## Trust boundaries and limits

The pinned snapshot can additionally contain bounded untrusted Markdown documentation (100 files, 2 MiB total) and package manifests (50 files, 1 MiB total). Both share the existing 1,000-entry, per-file, total-byte and request limits. Documentation is displayed as text and its statements are labeled documented rather than verified.

CodeDNA analyzes untrusted repository text; it does not execute it. The public acquisition endpoint accepts only canonical GitHub repository URLs and contacts fixed GitHub API URLs without following redirects. It resolves the default branch to a commit, verifies tree and Git blob hashes, and does not treat a truncated tree as complete. The optional `GITHUB_TOKEN` is server-only; do not expose it through `NEXT_PUBLIC_` variables, logs, browser bundles or client errors. Repository content and analysis are returned to the requesting browser, which temporarily holds the imported snapshot in session storage; other scripts running in the same origin can access it. Learning progress is also kept in session storage, keyed by repository identity and revision, and may reveal which lessons or files were visited. Avoid importing sensitive code and use a dedicated origin with a restrictive deployment policy. Browser storage may fail due to quota or privacy settings.

Defaults cap acquisition at 1,000 files, 2 MiB per file, 50 MiB total, 1,003 upstream requests, four concurrent upstream requests and 60 seconds. Only supported TypeScript/JavaScript and relevant config files are acquired. Skipped files are reported as partial; truncated trees fail. Production acquisition is disabled by default because no distributed limiter is configured; a deployable integration must be implemented before enabling it. The endpoint accepts at most 4 KiB in a request body, with a five-second body deadline, and allows two concurrent requests and 30 requests per minute **per process**. These safeguards are neither per-user nor distributed; instances and restarts do not share counts.

**Public release blockers:** put a distributed rate limit and concurrency/queue limit at a trusted ingress across all instances, configure request size and body timeouts there, and prevent direct bypass of that ingress. Do not trust client-supplied forwarding headers without a controlled proxy. Server analysis now uses a worker with a 15-second deadline and V8 heap limits, but a worker is not a security sandbox and does not bound all process or native memory. For public operation, add OS/container CPU and memory isolation and verify worker packaging in the chosen deployment. Establish deployment-specific logging, monitoring and incident response without logging source or tokens. Perform manual browser and extension-host checks before release.

## Local workspaces and extension

The extension only analyzes trusted local `file:` workspace folders. VS Code search exclusions and generated/dependency filters apply; files are capped at 1,000, 2 MiB each and 50 MiB total, with a 30-second acquisition deadline and explicit partial diagnostics. It never sends local source to GitHub or another network service. Source and filenames can still be sensitive in local memory and graph metadata; workspace progress and up to three analysis results are held in memory. Local source is not sent to the webview, although extracted graph labels, literals and evidence may be visible there.

Paths must remain relative to the selected folder, symlinks are rejected, resolved paths must remain within it, and reads use a bounded file descriptor with identity and content-stability checks before and after reading. POSIX uses `O_NOFOLLOW` for the final component. These checks reduce but cannot eliminate concurrent ancestor replacement, hard-link, or same-inode modification races; VS Code's separate open-document operation has a similar race. Treat hostile concurrently modified workspaces as unsupported; do not rely on the extension as an OS sandbox. Remote/virtual workspaces and untrusted folders are unsupported. Platform symlink behavior should be tested in a real Extension Development Host before release.

The webview uses local assets, a nonce for scripts and a CSP blocking network connections. Graph rendering needs inline styles. Webview requests are versioned, allowlisted, bounded, and checked against snapshot paths; the host controls source opening. A compromised host or another extension is outside this boundary. Worker cancellation and deadlines reduce stale work, but cannot replace process-level resource isolation; browser session and host-to-webview structures are not fully schema-validated against hostile same-origin or host manipulation.

## Dependencies and release checklist

The PostCSS override patches the Next.js transitive dependency; reassess it when upgrading Next.js. Vitest 4 removes the audited critical Vitest/Tinypool findings. The development-only VSIX packaging chain currently contains `@azure/msal-node@6.0.1` affected by GHSA-xcx6-jx8p-x3h5 in its authorization code flow. Local `vsce package --no-dependencies` does not invoke that flow, but the advisory remains unresolved: do not use the affected tooling for authentication/publishing. The patched `@azure/identity` release requires Node 22 whereas the workspace supports Node 20; resolve runtime policy and verify compatibility before publishing. Review `pnpm audit` regularly, including moderate and development findings.

Next.js 15.5.28's `eslint-config-next` declares ESLint 7–9 peers, not ESLint 10; the standalone plugin does not declare an ESLint peer, so its compatibility cannot be inferred. The current flat configuration does not install Next-specific rules and Next build warns accordingly. Keep this visible until a tested supported configuration or a planned upgrade is adopted. Extension repository metadata matches the verified Git remote. No project license has been invented; establish owner-approved licensing before distributing a VSIX.

Local development's GitHub importer can fetch a commit-pinned archive from `codeload.github.com` without forwarding the GitHub token. It validates supported files against the pinned Git tree and enforces compressed and expanded archive limits. An archive may contain unsupported files that count toward those download limits. The production endpoint remains disabled.
Capability status is derived locally from existing analysis results; it does not execute repository code or contact an AI service. A recoverable UI-flow analyzer exception is reported without exposing the exception text. Worker timeout, cancellation, snapshot validation and acquisition errors continue to fail closed.

## AI explanations

Behavior discovery, stories, retrieval and deterministic answers run locally and never contact an AI service. Optional AI answers are off by default and enabled only by server-side environment configuration; credentials are read by API routes only and are not part of any client bundle or status response. `/api/ai/explain` requires a same-origin JSON request, an explicit `consent: true` for that request, a bounded evidence bundle (at most 16 excerpts, 2,000 characters each, 24,000 in total) and is rate limited in memory; it is disabled in production unless `CODEDNA_AI_ALLOW_PRODUCTION=1`, because there is no distributed limiter. Excerpts are redacted for obvious secret assignments (a heuristic, not a guarantee), so source may still contain sensitive content: the Ask view states what will be sent and to what kind of endpoint before the user agrees. Repository text is placed only in a delimited data block and the prompt tells the model to treat it as untrusted data; this reduces but cannot eliminate prompt injection, so output is never executed and is validated: invalid JSON, unknown citations and unsupported navigation targets are removed or the answer is discarded. AI text is labeled inferred, never verified, and citations show what the model referenced, not that its claims are correct. Provider errors, rate limits and timeouts return generic messages and leave deterministic answers available. No repository code is executed and the production GitHub importer remains disabled.
